WHAT THE IDB IS
---------------
osdsys_dump.idb = your 3-year-old annotated database of the emulator dump
"osdsys_dump_200000". Provenance now closed (was an open question):

  - Its RAM segment (0x200000..0x2a7eb5, 687,797 bytes) is BYTE-IDENTICAL
    to /u/aap/src/osdsys/expanded.bin (687,796 B + 1 stray byte) — i.e. the
    payload your launcher decompresses. The decompressed OSDSYS blob and the
    emulator dump are the same bytes.
  - So this is not just "the boot animation program": it is the WHOLE
    OSDSYS EE program — boot browser + memory-card/DVD/config machinery +
    the boot animation — linked to run at 0x200000.
  - Built with the SCE toolchain ee-gcc-3.2-final-rc2 (full
    /proj/ee-toolchain/... paths in the strings). Same toolchain family as
    your osdbits Makefile (/usr/local/sce/ee), so instruction-level
    comparison of your code vs the binary is meaningful.
  - Extra "low" segment 0x1f0000..0x200000 (64 KB) = separate dump of the
    region below the program; holds OSDSYS globals (history @0x1f0138,
    systemState @0x1f05e8, dbuff @0x1f0a10, evenOddFrame/Field,
    screen_width/height @0x1f0c40..). BSS segment 0x2a7f00..0x3f32b0
    (1.35 MB) = the program's scratch.
  - 1527 functions in the RAM segment; you named ~756 things (mostly
    animation-side); 68 of your old comments survive (GS-register param
    docs on the pktSet*/vif1Set* family, jumptable case comments).

HOW I COMPARED
--------------
Reconstructed the loaded image from the IDB (python-idb GetManyBytes, the
venv at /u/aap/src/osdsys/.venv still works), disassembled both sides with
system objdump -m mips:5900, and per function computed:
  mnem = difflib ratio on the mnemonic sequence (robust to addresses/
         register allocs), n = instruction counts.
"m=1.00" = same instruction sequence, same constants, only addresses differ.

VU1 MICROCODE
-------------
The 7 VU programs (your vucode_1..7, byte-exact in the blob at 0x2678f0+)
are the animation's geometry pipeline (4 dir lights, morph 2/4/6/8 verts,
backface cull — matches your notes.txt: this is the cubes/towers pipeline).
osdbits does NOT contain them: your Makefile has no .dsm/.vsm objects and
your draw code does EE-side math only (libvu0). The real draw path feeds
the cubes/towers through VU1 — that's the biggest architectural gap
between osdbits and the real thing, together with the missing renderer
core at 0x230000..0x247000.
